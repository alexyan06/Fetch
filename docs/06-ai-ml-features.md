# AI / ML Features

**Goal:** avoid the "we called an LLM API and called it AI" tell that judges see constantly. The data we have (headcount over time, burn rate, ticket volume — structured, numeric, time-series-ish) is a genuinely good fit for real classical ML, not just LLM wrapping.

## Core real-ML additions (do these — recommended, ~1-2 hrs total via scikit-learn)

### 1. Trained classifier replacing the auto/human-review threshold
Instead of a hardcoded rule ("more than X new hires = big change"), generate synthetic labeled training examples (fake company events labeled "should a human review this or not") and train a real classifier (logistic regression or gradient-boosted tree). **This literally *is* the core product decision engine, upgraded from rules to a real model** — not a bolt-on. Demo artifact: a feature-importance bar chart ("headcount growth rate: 40% of the decision, revenue volatility: 25%...") — real, honest, explainable.

### 2. Anomaly detection replacing "any change = trigger"
Use isolation forest (or a simpler z-score approach) to learn what's *normal* pace-of-change for a given company, and only flag genuinely unusual events — a company with a steady predictable hiring rhythm doesn't get flagged for a normal hire; a company that suddenly triples its pace does. Demo artifact: a trend line chart with the anomalous point highlighted in red.

## LLM layer (still valuable, just a different category — keep it clearly separate from "the real ML" in how it's talked about)
- **Explainability chat agent**: judge types "why does this company need more Cyber coverage?" → grounded answer citing the actual pulled data. Cheap to build (LLM + read access to already-fetched data + good system prompt), high demo impact.
- **Forward-looking narrative**: simple trend projection + a sentence generated by the LLM ("at this hiring pace, expect to cross your EPLI threshold in ~6 weeks").

## Stretch ML (only if far ahead of schedule)
- **Clustering** (k-means-style, unsupervised) — group companies by risk profile, show something like "this company just moved into the same cluster as your highest cyber-risk customers." Nice scatter-plot visual, genuine unsupervised learning.
- **Text classification via embeddings** on ticket data — judge whether a support ticket is *actually* security-related (semantic similarity) rather than naively counting all tickets as risk signal. Real applied NLP, distinct from just summarizing text with an LLM.

## Priority order if time runs short
1. Classifier (#1) — it's structurally the product's core decision, not optional.
2. Anomaly detection (#2) — cheap, great visual, prevents "flags everything" demo failure mode.
3. Explainability chat (LLM layer).
4. Everything else is genuine stretch.
