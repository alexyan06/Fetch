# Demo & Pitch Narrative

## The core "wow" moment
Live, in front of judges: simulate a trigger event in a sandbox account (e.g., add an employee via the BambooHR test Linked Account). Watch the system react in real time —
- **Small change** → coverage recommendation auto-updates on screen immediately, with a plain-English explanation citing the exact data point that caused it.
- (If time allows a second beat) **Large change** → instead of auto-updating, the system produces a written recommendation and hands it to a "human" for one-click approval — demonstrating the judgment layer, not just reflexive automation.

## Suggested demo structure
1. **Open on scale, not on one company.** Show the portfolio dashboard — 15-20 simulated companies, sorted by "needs attention now." Frames the problem as a real operational one (Corgi has thousands of customers; nobody's watching all of them), not a toy.
2. **Zoom into one company** and trigger the live event. This is the money shot — keep it simple and rehearsed so it's reliable live.
3. **Show the explanation/receipt** — the specific data point + reasoning behind the change (ties to the ML feature-importance and/or anomaly-detection visuals — see file 06).
4. **(Tier 2) Let a judge ask the chat agent a "why" question live** — interactive proof it's not canned.
5. **Close on the honest competitive positioning** (see below) — this is a strength, not a weakness, if delivered with confidence.

## How to handle the "hasn't someone done this?" question
Don't wait for a judge to raise it — get ahead of it:
> "Vouch — Corgi's most direct competitor — proved this general pattern works back in 2024, connecting to Carta and recommending coverage updates on funding events. They called it an industry first. But that's one data source, one trigger type, and a notification. We built the general version: any connected business tool, multiple trigger types, real automatic execution for the safe cases, and a real trained model — not hardcoded rules — deciding what's safe to automate versus what needs a human."
This shows real market research (a strength on its own) and reframes "not entirely novel" as "we understood the space deeply enough to build the more ambitious version."

## Things to visibly prove, not just claim
- **Real ML, not just an LLM call**: show the feature-importance chart and the anomaly-highlighted trend line on screen — these are the visual proof points that this isn't "we called an API and called it AI."
- **Real Merge depth**: name-drop the specific categories/Common Models used (HRIS Employee/Employment, Accounting Transaction/CompanyInfo, etc.) rather than speaking generically about "an API."
- **Real Corgi understanding**: use their actual coverage-line names (CGL, D&O, Tech E&O, Cyber, EPLI, etc.) and their own FAQ language for the trigger events — signals genuine product research, not a generic insurance demo.

## Safety net
Have a backup recorded video of the full demo flow in case live Wi-Fi/sandbox/API issues strike at 6am — standard hackathon insurance, doesn't cost much to prepare in the last polish window.
